The pilot order, and what each step is watching for

# Step Watching for
E1Wizard offers the providerThe key-size list, read from NCRYPT_LENGTHS_PROPERTY
E2Install a standalone test CAKey creation as the service account; the PIN reaching a headless process
E3Issue a certificate, publish a CRLThe main signing path through ncrypt.dll
E4Renew the CA cert, new keyThe test most likely to fail — which call pattern ADCS really uses
E5Restart the service, then rebootLazy initialisation; PIN availability at boot before any logon
E6Revoke, then certutil -verifyEnd-to-end correctness, not merely API success
E7Two CAs, or a second KSP consumerThe session pool and per-process singleton under contention

Throw the test CA away afterwards. Never pilot against a CA whose certificates anything trusts. Some of what is written above about the wizard and about renewal is inference from the CNG contract, not observation — no version of this provider has been loaded by ncrypt.dll.
