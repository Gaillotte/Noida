setx /M KSP_DEBUG 1  # DebugView, pilot only

Registration is two things, not one

The binary goes in with BCryptRegisterProvider; the algorithm list goes in with BCryptAddContextFunctionProvider. Writing the registry values by hand does only the first: the provider loads, reports no algorithms, and anything discovering providers by algorithm skips it.

Two tokens, not two label prefixes

Set the pair and NCRYPT_MACHINE_KEY_FLAG selects which token — own PIN, own session pool. Without them the scopes are a label prefix inside one token, which is namespacing, not isolation. Half-configured is refused.

Then restart anything already running. CNG reads the provider list at process start, so certsrv will not see a newly registered provider until it restarts. And remove SOFTHSM2_PIN once the blob is provisioned, or you cannot tell which credential a successful login used.

set_ksp_pin.ps1 reads the PIN with Read-Host -AsSecureString, so it never reaches the process list or the shell history · 13 / 15
