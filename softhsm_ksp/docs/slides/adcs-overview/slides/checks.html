Five static checks, because prose does not stay true

The project's most persistent defect is not a bug. It is a summary of a fact, sitting next to the fact, not updated with it — found in the feature matrix, the property tables, the test counts, the registration script and the vendor-facing requirements document. Each one became a machine-checked invariant instead.

check_mock_drift.py

The test mock against the real Windows headers — values and typedef widths. The mock once invented two constants and mis-valued two more, and every test passed because the tests read the same wrong numbers.

check_registration.py

The registration script against what the provider advertises, both ways. Found AES-CMAC advertised and never registered, and RSA decryption implemented and undiscoverable — never published under the asymmetric-encryption interface.

check_property_docs.py

The property tables against the dispatch chains, in both directions and including the read and write columns. Its first run reported four real defects — one documented property did not exist at all.

check_test_counts.py

Every documented suite and assertion figure against the suite's own run log. The historical session entries are deliberately excluded — a check that flags the record as drift pressures the next reader into falsifying history.

check_generated_artifacts.py

Four generated documents against their inputs, by fingerprint. It compares inputs rather than outputs, because every artifact embeds a date and two are binaries with unstable internal ordering.

The weakest gate was the one nobody could run

The mingw cross-compile is the only check that compiles Windows-only code, and it did not promote an implicit declaration to an error where the unit build did. It let a truncated Win64 heap pointer through with exit 0.
