The discipline

A green test proves nothing until you have watched it go red

Every claim in this project is established by breaking the code and confirming the suite catches it. The habit exists because vacuous tests kept passing: one asserted a defect as the expected behaviour, another compared two handles that could be swapped freely.

Five defects the mock could not see

  • ECDSA signing had never worked against a conformant token — the provider decoded DER where v2.40 mandates raw r‖s, and the mock returned whatever DER the test had just built
  • A size query poisoned the session pool
  • A deleted key left its certificate on the token
  • HMAC and CMAC signing had never worked
  • A key opened by name lost its modulus size, so every signature failed at CNG's first call

And three traps in the harness itself

  • Building one test binary silently rebuilt nothing, so four consecutive fault injections ran against a stale binary and looked undetected — the worst possible failure for the one tool whose job is to show a test can fail
  • Ten stubs were never checked against the real prototype, so a signature change produced ten segfaults and no diagnostic
  • A grep for a fix matched the comment describing the fix, and reported ten files as correct when none was
