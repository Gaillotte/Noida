Installation · step 1 of 3

Build the DLL — and find the header first

Prerequisites

  • Windows 10/11 x64, elevated prompt
  • Visual Studio with the x64 toolset, and CMake
  • ncrypt_provider.h — associated with the Cryptographic Provider Development Kit; absent from the SDK, a WDK install and mingw-w64
  • A PKCS#11 module: SoftHSM2 for the lab, the vendor's library for production
  • An OV or EV code-signing certificate, bought by a verified legal entity

Commands

git submodule update --init --recursive
.\softhsm_ksp\tools\build_softhsm_windows.ps1

cd softhsm_ksp; mkdir build; cd build
cmake .. -A x64 `
 -DSOFTHSM2_DIR=..\..\softhsm2-install `
 -DCPDK_INCLUDE_DIR=C:\cpdk\include
cmake --build . --config Release

Omit the header and CMake skips the DLL

Deliberately — a provider with no entry point is worse than no provider. The build warns instead, and the other nine files still compile.

Settle signing in the first hour

Whether ncrypt.dll refuses to load an unsigned user-mode KSP is unconfirmed. If it does, that is a procurement lead time, not a code change.
