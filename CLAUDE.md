## What This Project Is

A complete **Microsoft CNG (Cryptography Next Generation) Key Storage Provider (KSP)**
that delegates all cryptographic operations to **SoftHSM2** via the **PKCS#11 v2.40**
interface. Targets Windows 10/11 x64 (MSVC / CMake). The KSP is a DLL that Windows
loads when an application calls `NCrypt*()` API functions.

The main deliverable is `softhsm_ksp/` — a self-contained project with source, tests,
tools, and documentation.

## Work Completed in Prior Sessions

### Session 5 — Market audit
- **`docs/11-market-comparison.md`** — capability audit of shipping CNG KSPs
  (Microsoft Software / Platform Crypto, AWS CloudHSM, Utimaco, Thales,
  Entrust, Securosys) against this project, with an A/B/C evidence grade on
  every claim
- **Key finding**: `EDDSA_ED25519`, `EDDSA_ED448` and `HMAC_SHA*` are **not
  standard CNG algorithm identifiers** — CNG defines no EdDSA algorithm ID at
  all. Those features are reachable only from an application written against
  this KSP specifically, and cannot be BCrypt-verified end to end. `AES` and
  the ECB/CBC/GCM chaining modes *are* standard; `ChainingModeCTR` is not.
- Every other surveyed provider exposes only RSA + ECDSA + ECDH on NIST curves
- **`docs/12-pkcs11-requirements.md`** — the PKCS#11 backend contract extracted
  from source: 22 Cryptoki functions, 20 dispatch mechanisms, 18 attributes,
  5 parameter structs, organised into 5 capability tiers with an HSM
  evaluation checklist. Tier 1 (RSA + ECDSA, market parity) needs 6
  mechanisms and 17 functions.

## Key Technical Facts

### Architecture
```
Windows Application
    ↓ NCrypt*() API
ncrypt.dll ──── registry: HKLM\...\CNG\KeyStorageProviders\SoftHSM KSP
    ↓ NCRYPT_KEY_STORAGE_FUNCTION_TABLE (22 functions)
softhsm_ksp.dll
    ├── ksp_*()           22 CNG functions
    ├── p11_context.c     PKCS#11 singleton (LoadLibrary + C_Initialize)
    ├── p11_session.c     Pool of 16 sessions (Windows semaphore)
    └── p11_utils.c       Mechanisms, DER decode, key export
    ↓ C_XXX() via CK_FUNCTION_LIST
softhsm2-x64.dll          PKCS#11 v2.40 — encrypted SQLite storage
```

### Magic Numbers
- `KSP_PROVIDER_MAGIC = 0x4B535050` — validates `(KSP_PROVIDER *)hProvider`
- `KSP_KEY_MAGIC = 0x4B53504B` — validates `(KSP_KEY *)hKey`

### Session Pool
- 16 sessions max, guarded by `CreateSemaphore` + `CRITICAL_SECTION`
- `InitOnceExecuteOnce` for one-shot PKCS#11 initialization (one-per-process)

### Supported Algorithms

| Key Type | CNG Alg ID | Sizes | PKCS#11 Gen Mechanism |
|---|---|---|---|
| RSA | `RSA` | 2048, 3072, 4096 bits | `CKM_RSA_PKCS_KEY_PAIR_GEN` |
| ECDSA | `ECDSA_P256/384/521` | 256, 384, 521 bits | `CKM_EC_KEY_PAIR_GEN` |
| ECDH | `ECDH_P256/384/521` | 256, 384, 521 bits | `CKM_EC_KEY_PAIR_GEN` (CKA_DERIVE=TRUE) |
| EdDSA | `EDDSA_ED25519/ED448` | 255, 448 bits | `CKM_EC_EDWARDS_KEY_PAIR_GEN` |
| AES | `AES` | 128, 192, 256 bits | `CKM_AES_KEY_GEN` |
| HMAC | `HMAC_SHA1/256/384/512` | 160–512 bits | `CKM_GENERIC_SECRET_KEY_GEN` |

### Signing Operations

| Mode | CNG Flag | PKCS#11 Mechanism | Hashes |
|---|---|---|---|
| RSA PKCS#1 v1.5 | `NCRYPT_PAD_PKCS1_FLAG` | `CKM_RSA_PKCS` | SHA-1/256/384/512 |
| RSA PSS | `NCRYPT_PAD_PSS_FLAG` | `CKM_RSA_PKCS_PSS` + `CK_RSA_PKCS_PSS_PARAMS` | SHA-1/256/384/512 |
| ECDSA P-256/384/521 | 0 (no padding) | `CKM_ECDSA` | SHA-256/384/512 recommended |
| EdDSA Ed25519/Ed448 | 0 (no padding) | `CKM_EDDSA` | Hashes internally |
| HMAC | 0 | `CKM_SHA*_HMAC` | Secret-key MAC |

ECDSA: SoftHSM2 returns DER → `P11_DecodeDerEcdsaSignature()` converts to raw r‖s (Windows format).
Signature sizes: P-256 → 64 B, P-384 → 96 B, P-521 → 132 B, Ed25519 → 64 B, Ed448 → 114 B.
EdDSA signatures are already raw — no DER conversion.

### Key Agreement (ECDH)

`KSP_SecretAgreement` → `CKM_ECDH1_DERIVE` with `CKD_NULL` (raw Z).
`KSP_DeriveKey` supports `BCRYPT_KDF_RAW_SECRET` only; hash KDFs return `NTE_NOT_SUPPORTED`.
Both keys must be on the same curve or the call returns `NTE_BAD_ALGID`.

### Symmetric Encryption (AES)

Chaining mode comes from `NCRYPT_CHAINING_MODE_PROPERTY`, IV from
`NCRYPT_INITIALIZATION_VECTOR` — both key properties, not call flags.
ECB / CBC / CBC_PAD / CTR / GCM supported; CCM and CFB return `NTE_NOT_SUPPORTED`.

### Decryption Operations (RSA AT_KEYEXCHANGE only)

| Mode | CNG Flag | PKCS#11 Mechanism |
|---|---|---|
| PKCS#1 v1.5 | `NCRYPT_PAD_PKCS1_FLAG` | `CKM_RSA_PKCS` |
| OAEP | `NCRYPT_PAD_OAEP_FLAG` | `CKM_RSA_PKCS_OAEP` + `CK_RSA_PKCS_OAEP_PARAMS` (SHA-1/224/256/384/512, optional label) |

### Key Security Attributes
All keys: `CKA_TOKEN=TRUE`, `CKA_SENSITIVE=TRUE`, `CKA_EXTRACTABLE=FALSE`
AT_SIGNATURE: `CKA_SIGN=TRUE` | AT_KEYEXCHANGE: `CKA_DECRYPT=TRUE`

### Known Limitations
- No raw RSA (`CKM_RSA_X_509`) — SoftHSM2 limitation
- No private key import — HSM design
- Only first token-present slot used
- RSA sizes outside {2048, 3072, 4096} → `NTE_BAD_LEN`
- AES sizes outside {128, 192, 256} → `NTE_BAD_LEN`
- AES-CCM and AES-CFB → `NTE_NOT_SUPPORTED` (no SoftHSM2 mechanism wired)
- Hash-based KDFs in `NCryptDeriveKey` → `NTE_NOT_SUPPORTED`
- DES/3DES, DSA, PKCS#3 DH, GOST — deliberately out of scope
- Raw-hash and sign-with-integrated-hash mechanisms are unreachable by design
  (CNG always supplies a pre-computed digest to `NCryptSignHash`)

## Build Instructions (Windows)

```powershell
# 1. Initialise submodule
git submodule update --init --recursive

# 2. Build SoftHSM2 2.7.0 (OpenSSL, x64) — in a VS x64 Native Tools prompt
.\softhsm_ksp\tools\build_softhsm_windows.ps1
# Output: softhsm2-install\  (DLL inside)

# 3. Build the KSP DLL
cd softhsm_ksp
mkdir build && cd build
cmake .. -G "Visual Studio 17 2022" -A x64 -DSOFTHSM2_DIR=..\..\softhsm2-install
cmake --build . --config Release
# Output: softhsm_ksp\build\Release\softhsm_ksp.dll
```

## Code Conventions

- **Language**: all comments and identifiers in **English**
- **Warnings**: zero at `/W3` MSVC
- **Memory**: `HeapAlloc` / `HeapFree` on `GetProcessHeap()` only
- **Naming**: `KSP_` prefix for KSP layer, `P11_` prefix for PKCS#11 layer
- **Handles**: direct cast `(KSP_PROVIDER *)hProvider`, validated by `dwMagic`
- **Thread-safety**: all 22 KSP functions are re-entrant
