KMIP 2.1 Server with PKCS#11 HSM Integration

1. Architecture Overview

CryptoHub Lite is a web-based cryptographic management platform built on a KMIP 2.1 server that delegates all key storage and cryptography to a PKCS#11 HSM (SoftHSM2). The system provides both a web portal and a KMIP protocol interface — two views of one system, not two separate systems.

10. Known Limitations

⚠️ Stated limitations (not hidden):

  • Concurrency is capped — All HSM work is serialised through one PKCS#11 session. A session pool was rejected due to python-pkcs11 calling C_Initialize(NULL).
  • No high availability — Single API process, single KMIP process, single token.
  • No metadata/HSM reconciliation — Divergence between the database and the token is not detected automatically.
  • Batch operations are not atomic — A partial batch does not roll back.
  • No cryptoperiod enforcement — Rotation is a manual action.
  • Audit trail is append-only but not tamper-evident — Direct database access can alter it.
  • SoftHSM2 is not FIPS 140-2/3 or Common Criteria validated — Correct for development; production needs validated hardware.

12. Quick Start Commands

# Prerequisite: Docker Desktop running

# Clone and setup
git clone  && cd Kmip
./cryptohub_lite/scripts/setup.sh    # Windows: cryptohub_lite\scripts\setup.cmd

# Docker Compose commands
C=cryptohub_lite/docker-compose.yml

docker compose -f $C up -d --build     # start / rebuild
docker compose -f $C ps                # status
docker compose -f $C logs -f api       # follow logs
docker compose -f $C down              # stop
docker compose -f $C down -v           # stop and DESTROY all data

# Run tests
docker compose -f cryptohub_lite/docker-compose.yml exec api \
    sh -c 'cd /app && python -m pytest kmip_pkcs11/tests -q'

# Expected: 624 passed
